Tree
A few points:
So far, we have said that the tree is a non linear data structure.  A tree is an acyclic, connected graph. A 
tree of n nodes has n -1 branches or edges. If we add an edge, a cycle is formed. If we remove an edge, 
the connectivity between every pair of nodes is lost.
A general tree is defined as 
a) Either empty or
b) Has a root followed by number of subtrees.
Some of the terms we use with the tree are:
Root, nodes, internal nodes, leaves, branches, path, ancestor, descendant 
Parent, child, grand parent, grandchild, siblings, uncle
Height, depth, level.
Degree of a node.

Traversals:
1. Inorder traversal of a binary tree:
We can visit all the components in an array or a list from one end to another. It is not possible to 
do so in case of a tree. One of the ways of visiting all the components in a binary tree is to visit 
the left subtree somehow and then the root and then the right subtree somehow. If the tree is

----------------------------------------

===== Page 5 =====

empty, there is nothing to visit. As the left and the right subtrees are trees, we could apply this 
logic recursively.
Before visiting A, we visit left sub tree of A – that is the subtree B.
Before visiting B, we visit left sub tree of B – that is the subtree D.
Left sub tree of D is empty. So visit D.
Right sub tree of D is empty. So the sub tree D has been visited.
Left sub tree of B has been visited. So visit B.
Now visit the right sub tree of B. 
Next we visit E.
Now, the left sub tree of A is visited. So visit A and then its right subtree.
This results in visit C  and then visit F.
So the traversal of this tree will result in :
D B E A C F

If the tree is not empty

If the tree is not empty,

 Then visit the right subtree in preorder

In this traversal, 
If the tree is not empty, 
We visit left subtree in postorder
 Then visit the right subtree in postorder
Then the root

Implementation of Binary Search Tree:
To start with, we will make a simple example of binary trees. We will use a special binary tree 
called binary search tree.
In a binary search tree, every component has a key. The components are arranged based on the 
key. 
If the tree is empty, the component is put at the root. 
Otherwise, if the key in the component at the root is higher than the key in the new component, 
we will insert in the left subtree.
Otherwise, we will in the right subtree.
You will observe that the insertion always happens as a leaf.
One of the implementations will be as follows.
The tree has a root. This is like a list having a head.
The root points to a node structure. 
The node structure has a component – called key – in this example.
Apart from that, it has two pointers – which point to the left and the right sub trees.
struct tree

typedef struct tree tree_t;

Insert:
void insert(tree_t *ptr_tree, int key)
{
node_t *temp = (node_t*)malloc(sizeof(node_t));
temp->key_ = key;
temp->left_ = temp->right_ = NULL;
ptr_tree->root_ = insert_recursive(ptr_tree->root_, temp);
}
The above tree routine creates a node. Assumes that it succeeds in memory allocation. 
Populates the node. Calls the insert_recursive function of the node to return the root.
This function is very interesting. If the tree is empty, then this new node becomes the root.
Otherwise based on the comparison of the key, we try to insert in the left subtree or the right 
subtree. If the insertion is in the left subtree, then left of the root is the root for that subtree.
Similarly, if the insertion is in the right subtree, the right of the root is the root for that subtree.
So, the return value of the function is assigned to the appropriate root.

Search for a key in a binary search tree:
A binary search tree is organized based on a predicate applied at the root. We use this 
predicate while inserting as well as searching. 
While inserting if the root is empty, the node with the key is made the root.
Otherwise, we compare the key with the key at the root. If the key is less than the key at the 
root, we insert in the left subtree otherwise in the right subtree.
There are two aspects to searching in a tree. 
-
How to search?
-
What to return?
If the tree is empty, the key is not found. 
If the key matches the key at the root, the key is found at the root. 
Otherwise if key is less than the key at the root, we search the left subtree recursively 
Else search the right subtree recursively.

How to store a tree and how to restore a tree?
If a list has to be stored, we could traverse and right the components to a file.  We can restore the list by 
reading the components from the file and attaching them at the end of the list.
A list is a linear data structure. So we cannot do the way we have stated above.
A tree is non linear. A single traversal will not define the tree completely. 
For example, if a tree of 3 nodes has an inorder traversal A  B C, there are 5 possible trees which can 
produce the same inorder traversal.
An inorder and a postorder traversals of a tree uniquely defines a tree. Given the two traversals, we can 
reconstruct the tree.
Let us take an example to illustrate. 
                         A
                       /   \
                      B     C
                     / \   / \
                    D   E F   G
                       /             \
                      H           I
                               /
                              J
There are exactly 10 nodes:

----------------------------------------

===== Page 22 =====

A, B, C, D, E, F, G, H, I, J
The inorder traversal of the tree : D B H E A F C G J I
The post order traversal of the tree : D H E B F J I G C A
To reconstruct the tree, traverse the post order traversal from the right. The last node A has to be the 
root of the whole tree. Therefore, A is the root and A divides the inorder traversal into two parts. All 
nodes to the left of A are in left subtree of A and all the nodes to the right of A in the right subtree.
So, we know the root of the tree.
Next to the right of A in postorder traversal is C. C is to the right of A in inorder traversal. C is the root of 
the right subtree of A.
This way we may continue to build the whole tree.
