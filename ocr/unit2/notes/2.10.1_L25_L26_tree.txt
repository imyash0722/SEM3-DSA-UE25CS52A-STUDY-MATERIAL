A few points:
So far in this course, we have discussed that a data structure has number of components. Each data 
structure is a type – called Abstract Data Type and each data structure supports a set of operations 
meaning for that data structure.
Each component knows about itself very strongly. It is cohesive. It does not know in which data structure 
it will be put. 
Each data structure knows little about the component it contains. Whenever it requires any services 
from the component, it will delegate the function to that of the component. It does not probe inside the 
component to see what it contains. So, the data structure is also cohesive.
There is not much of dependency between the data structure and the component. They are not coupled. 
By this way we realize one of the requirements of software development – high cohesion and low 
coupling.
We have discussed a few data structures like list, stack, queue, doubly linked list, circular queue. The 
components of all these data structures are in a line – they are linear. Even though the doubly linked list 
has two pointers in each node, they still are in a line. These data structures are called linear data 
structures.
There are many situations which cannot be captured in a line.

Tree:
A tree is a non-linear data structure used to represent hierarchical relationships. Unlike arrays, stacks, 
queues, and linked lists, where elements are arranged sequentially, a tree organizes elements in a 
parent–child structure.
This is an example of a tree. 
Terminology from genealogy:
We say that A is the parent. B, C, D are children of A. They may be unordered or ordered left to right. B 
has two children E and F. C has no children. D has a single child G. 
We say that A is the grand parent of E, F and G. We say that E, F, G are grand children of A.
B, C, D are siblings – children of the same parent.
A is an ancestor of B and also E. B and E are descendants of A.

Summary of Terminologies:
A tree consists of a set of nodes connected by edges.
Root: the topmost node of the tree. 
Parent: a node that has one or more children. 
Child: a node directly below another node. 
Siblings: nodes having the same parent. 
Leaf / External node: a node with no children. 
Internal node: a node having at least one child. 
Edge: connection between a parent and a child. 
Path: sequence of nodes connected by edges. 
Ancestor: a node occurring on the path from the root to a given node. 
Descendant: a node occurring below a given node. 
Subtree: a tree formed by a node together with all its descendants.

The height of a tree is the height of its root.

Inorder traversal of a binary tree:
We can visit all the components in an array or a list from one end to another. It is not possible to 
do so in case of a tree. One of the ways of visiting all the components in a binary tree is to visit 
the left subtree somehow and then the root and then the right subtree somehow. If the tree is 
empty, there is nothing to visit. As the left and the right subtrees are trees, we could apply this 
logic recursively.
Before visiting A, we visit left sub tree of A – that is the subtree B.
Before visiting B, we visit left sub tree of B – that is the subtree D.
Left sub tree of D is empty. So visit D.
Right sub tree of D is empty. So the sub tree D has been visited.
Left sub tree of B has been visited. So visit B.
Now visit the right sub tree of B. 
Next we visit E.

D B E A C F

Conversion of any tree to a binary tree:
A general tree might have nodes with any number of children. Processing such a tree is difficult. 
But, if we can represent the general tree as a binary tree, then processing becomes easy. 
A binary tree can represent only two properties – one for the left branch and one for the right 
branch. If we can match this to two properties of a general tree, then we can represent any 
general tree as a binary tree.
This is the way we do it.

Root of general tree will become the root of the binary tree

Child of the node in a general tree becomes the left child of that node in the binary tree

Sibling a node in a general tree becomes the right child of that node or attached to the right 
path.

Implementation of Binary Search Tree:
To start with, we will make a simple example of binary trees. We will use a special binary tree 
called binary search tree.
In a binary search tree, every component has a key. The components are arranged based on the 
key. 
If the tree is empty, the component is put at the root. 
Otherwise, if the key in the component at the root is higher than the key in the new component, 
we will insert in the left subtree.
Otherwise, we will in the right subtree.
You will observe that the insertion always happens as a leaf.
One of the implementations will be as follows.
The tree has a root. This like a list having a head.
The root points to a node structure. 
The node structure has a component – called key – in this example.
Apart from that, it has two pointers – which point to the left and the right sub trees.
struct tree 
{
node_t *root_;
};
typedef struct tree tree_t;
struct node 
{
int key_;
struct node *left_;
struct node *right_;
};
typedef struct node node_t;

Traversal:
Observe that the tree function disp calls disp_recursive of the node.
The disp_function of the node calls itself on its left subtree, displays the root and
Calls itself on its right subtree.
void disp(tree_t *ptr_tree)
{
printf("Tree : ");
disp_recursive(ptr_tree->root_);
printf("\n");
}
static void disp_recursive(node_t* temp)
{
if(temp)
{
disp_recursive(temp->left_);
printf("%d ", temp->key_);
disp_recursive(temp->right_);
}
}

Insert:
void insert(tree_t *ptr_tree, int key)
{
node_t *temp = (node_t*)malloc(sizeof(node_t));
temp->key_ = key;
temp->left_ = temp->right_ = NULL;
ptr_tree->root_ = insert_recursive(ptr_tree->root_, temp);
}
The above tree routine creates a node. Assumes that it succeeds in memory allocation. 
Populates the node. Calls the insert_recursive function of the node to return the root.
This function is very interesting. If the tree is empty, then this new node becomes the root.
Otherwise based on the comparison of the key, we try to insert in the left subtree or the right 
subtree. If the insertion is in the left subtree, then left of the root is the root for that subtree.
Similarly, if the insertion is in the right subtree, the right of the root is the root for that subtree.
So, the return value of the function is assigned to the appropriate root.
You may want to draw and check how this works for a tree of at least 3 nodes.
static node_t* insert_recursive(node_t* root, node_t* temp)
{
if(root == NULL)
{
root = temp;
}
else if(root->key_ > temp->key_)
{
root->left_ = insert_recursive(root->left_, temp);
}

Deinitialize:
Like other functions, deinit of tree calls the deinit_recursive of node.
void deinit(tree_t *ptr_tree)
{
deinit_recursive(ptr_tree->root_);
ptr_tree->root_ = NULL;
}
This recursive function on the node clears the left subtree recursively, then the right subtree 
recursively and then the root.
Please node that the order matters.
static void deinit_recursive(node_t* root)
{
if(root)
{
deinit_recursive(root->left_);
deinit_recursive(root->right_);
free(root);
}
}

Adding a few more functions in the interface of the tree:
Count the number of nodes 
int number_of_nodes(tree_t *ptr_tree);
This function of tree calls the recursive function of the node.
The number of nodes in an empty tree is 0.
Otherwise we count the root node and add the number of nodes in the left subtree and the right 
subtree.
// tree 
int number_of_nodes(tree_t *ptr_tree)
{
return number_of_nodes_recursive(ptr_tree->root_);
}
int number_of_nodes_recursive(node_t* temp)
{
if(temp == NULL)
{
return 0;
}
else 
{
return 1 + number_of_nodes_recursive(temp->left_) 
+ number_of_nodes_recursive(temp->right_);
}
}

Count the number of leaves
int number_of_leaves(tree_t *ptr_tree);
This function of tree calls the recursive function of the node.
The number of leaves in an empty tree is 0.
If both the left and right subtrees are empty, it is a leaf. We count it.
Otherwise we count the number of leaves in the left subtree and the number of leaves in the 
right subtree.
// node 
int number_of_leaves(tree_t *ptr_tree)
{
return number_of_leaves_recursive(ptr_tree->root_);
}
int number_of_leaves_recursive(node_t* temp)
{
if(temp == NULL)
{
return 0;
}
else if(temp->left_ == NULL && temp->right_ == NULL)
{
return 1;
}
else
{
return number_of_leaves_recursive(temp->left_) 
+ number_of_leaves_recursive(temp->right_);
}
