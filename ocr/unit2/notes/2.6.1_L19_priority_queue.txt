Priority Queue
So far, we have learnt the data structures list, stack, circular list and queue. We have observed that 
these are all abstract data types supporting a well-defined interface. We have also observed that each of 
these abstract data types could have different implementations. These data structures are found to be 
useful in different applications based on their interfaces.
A priority queue is an abstract data type in which each element is associated with a priority.
Unlike an ordinary queue, where elements are removed according to FIFO (First-In, First-Out) order, a 
priority queue removes the component with the highest priority first.
A priority is a number associated with each component. Higher the numeric value, could mean higher 
the priority. Or lower the numeric value could mean higher priority. In Unix, the latter concept is 
followed. You may know that there is a command called nice using which you can reduce the priority of 
your process – you can be nice to others!
In our examples, we will assume that higher the numeric value, higher the priority.
What is the rationale behind this? Let us consider a couple of examples.
The patients wait in a queue to consult a doctor. But what if a patient becomes critically ill? Should not 
that patient get immediate attention?
Several processes could be running on an operating system. A few of them may have to respond in real 
time. Should not these get preference over others?

Implementation of priority queue:
A priority queue is a collection of elements in which every element has an associated priority, and 
deletion returns an element having the appropriate extreme priority.
A priority is an abstract data type. As we know, an Abstract Data Type (ADT) specifies what operations 
are supported and what they mean, without specifying how those operations are implemented.
A priority queue can be implemented using any suitable underlying data structure. We will discuss the 
first 4 of the 5 listed below. The last one shall be discussed later in this course.

Implementation:
We shall discuss in this section whatever is common to all the four implementations. Implementation 
specific to a particular selected data structure shall be discussed separately.
Job : We have called each component of the priority queue as a job – a term commonly used in 
operating systems. The job structure has a unique number to identify the job and a priority to indicate 
how it should be handled. We are assuming that higher this number, higher the priority.
Each new job is given the job number in an increasing order. This job number will help us make out in 
which order the jobs have been services.
struct job 
{
int job_no_;
int priority_;
};
typedef struct job job_t;
This ADT job supports setting a job, displaying  the job and return the priority of a job when queried.
void set_job(job_t* ptr_job, int job_no, int priority);
void disp_job(job_t* ptr_job);
int get_priority(job_t* ptr_job);
The following is the implementation of this interface. The code is self explanatory.
void set_job(job_t* ptr_job, int job_no, int priority)
{
ptr_job->job_no_ = job_no;
ptr_job->priority_ = priority;

We support options for enque, deque and exiting the loop.
