# Unit 1: Dynamic Memory Management

## 5.1 Introduction

**Static vs Dynamic Variables:**
| Static (Stack) | Dynamic (Heap) |
|----------------|----------------|
| Created on block entry | Created on demand (`malloc`) |
| Destroyed on block exit | Destroyed on demand (`free`) |
| No control over lifetime | Full control over lifetime |
| Fixed size at compile time | Size determined at runtime |

**Dynamic Memory Management:** Manual control of memory allocation/deallocation using library functions.

---

## 5.2 Memory Areas

| Area | Description |
|------|-------------|
| **Stack** | Function frames, local variables, automatic lifetime |
| **Heap** | Dynamic allocation, manual lifetime, `malloc`/`free` |

---

## 5.3 Core Functions

### `malloc(size_t size)`
```c
void* malloc(size_t size);
```
- Allocates `size` bytes on heap
- Returns `void*` (generic pointer) — cast to desired type
- Returns `NULL` on failure
- Memory **uninitialized** (garbage values)

```c
int *p = (int*)malloc(sizeof(int));      // Single int
int *arr = (int*)malloc(sizeof(int)*4);  // Array of 4 ints
```

### `free(void* ptr)`
```c
void free(void* ptr);
```
- Returns memory to heap manager
- `ptr` must be **exactly** what `malloc` returned
- After `free`, pointer value unchanged (dangling!)
- Double free → undefined behavior

### `calloc(size_t nmemb, size_t size)`
```c
void* calloc(size_t nmemb, size_t size);
```
- Allocates `nmemb × size` bytes
- **Initializes all bytes to 0**
- Equivalent to `malloc(nmemb*size)` + `memset(0)`

```c
int *p = (int*)calloc(4, sizeof(int));  // 4 ints, all 0
```

### `realloc(void* ptr, size_t size)`
```c
void* realloc(void* ptr, size_t size);
```
- Resizes existing allocation
- May return **different pointer** (copy data to new location)
- Old data preserved (up to min of old/new size)
- On increase: new bytes uninitialized
- On decrease: excess data lost

```c
int *q = (int*)realloc(p, 10000);
```

## 5.4 Bookkeeping (Housekeeping)

**How `free` knows size:**
- `malloc` stores size in hidden metadata (bookkeeping)
- Metadata stored near allocated block (implementation-dependent)
- `free(ptr)` looks up metadata using `ptr` value
- Only works with **original** pointer from `malloc`

```
Heap Memory Layout:
+------------------+
| Bookkeeping info |  ← size, flags, etc.
+------------------+
| User Data        |  ← what malloc returns
+------------------+
```

## 5.5 Common Errors and Undefined Behavior

### Error 1: Freeing Wrong Pointer
```c
int *p = malloc(sizeof(int) * 4);
free(p + 1);  // TERRIBLE! No bookkeeping at p+1
```

### Error 2: Double Free
```c
int *p = malloc(sizeof(int));
free(p);
free(p);  // Undefined behavior
```

### Error 3: Free Non-Heap Pointer
```c
int a = 10;
free(&a);  // Stack pointer! Undefined behavior
```

### Error 4: Use After Free (Dangling Pointer)
```c
int *p = malloc(sizeof(int));
*p = 20;
free(p);
printf("%d", *p);  // DANGER! p is dangling
```

## 5.6 Aliasing and Safe Freeing

### Multiple Pointers to Same Block (OK to free via any):
```c
int *p = malloc(sizeof(int));
*p = 20;
int *q = p;        // Alias
free(q);           // OK! Same value → same bookkeeping
// p is now dangling
```
**Rule:** What matters is the **pointer value**, not the variable name.

### After Free: Set to NULL (Safe Practice)
```c
free(p);
p = NULL;  // Safe: dereferencing NULL = guaranteed crash (catchable)
```

## 5.7 Memory Leaks and Garbage

### Memory Leak (Lost Access):
```c
int *p = malloc(sizeof(int));
*p = 30;
p = malloc(sizeof(int));  // First block lost! No pointer to it.
```
- **Garbage:** Allocated memory with no accessible pointer
- **Memory Leak:** Garbage that accumulates
- **C has no garbage collector** — programmer's responsibility

### Dangling Pointer vs Memory Leak:
| Issue | Description | Where |
|-------|-------------|-------|
| **Dangling Pointer** | Pointer exists, memory freed | Stack/Heap |
| **Memory Leak** | Memory allocated, no pointer | Heap only |

## 5.8 `calloc` and `realloc` Details

### `calloc` Example:
```c
int *p = (int*)calloc(4, sizeof(int));
// p[0]..p[3] all 0
```

### `realloc` Behavior:
```c
int *q = (int*)realloc(p, new_size);
```

| Scenario | Behavior |
|----------|----------|
| **Increase size** | Old values copied; new bytes uninitialized |
| **Decrease size** | Values kept up to new size; excess lost |
| **New block needed** | Returns different pointer; old copied & freed |
| **Same block possible** | Returns same pointer (in-place) |
| **Failure** | Returns `NULL`; original `p` still valid! |

### Safe `realloc` Pattern:
```c
int *temp = realloc(p, new_size);
if (!temp) { /* handle error */ }
p = temp;  // Only assign on success!
```

## 5.9 Structure with Dynamic Members

### Case 1: Pointer to Stack Variable
```c
struct What { int *p; int a; };
what_t x, y;
x.a = 100; x.p = &z;  // z on stack
y = x;                 // y.p and x.p both point to z (alias)
x.a = 200;             // y.a unchanged, but *(y.p) changes!
```

### Case 2: Pointer to Heap — Free Creates Aliases
```c
x.p = malloc(sizeof(int));
*x.p = 10000;
y = x;                 // Both point to SAME heap block
free(y.p);             // x.p now DANGLING!
```

### Case 3: Break Alias After Copy
```c
y = x;                 // Both point to same heap
y.p = malloc(sizeof(int));  // New allocation for y.p
// x.p and y.p now point to DIFFERENT blocks — SAFE
```

### Case 4: Modify Original After Copy
```c
y = x;                 // Aliased
x.p = malloc(sizeof(int));  // x gets new block
// x.p and y.p now DIFFERENT — SAFE
```

### Case 5: Ground Pointer Without Free (Memory Leak)
```c
x.p = malloc(sizeof(int));
x.p = NULL;  // Lost access to heap block = GARBAGE = LEAK!
```

## Summary Table

| Function | Purpose | Initialization | Notes |
|----------|---------|----------------|-------|
| `malloc(size)` | Allocate | No (garbage) | Cast return value |
| `calloc(n, size)` | Allocate + zero | Yes (all 0) | Two args |
| `free(ptr)` | Deallocate | N/A | Must be exact `malloc` ptr |
| `realloc(ptr, size)` | Resize | Preserves data | May move block |

## Key Rules Checklist

| Rule | ✓/✗ |
|------|-----|
| Always check `malloc` return for `NULL` | ✓ |
| Use `sizeof(type)` not hardcoded bytes | ✓ |
| `free` only pointer returned by `malloc` | ✓ |
| Don't `free(p+1)` or `free(&stack_var)` | ✗ |
| Don't double free | ✗ |
| Don't use after `free` (dangling) | ✗ |
| Set pointer to `NULL` after `free` | ✓ |
| Use `calloc` for zero-init arrays | ✓ |
| `realloc` may return different pointer | ✓ |
| `struct` with `ptr` member: careful copy! | ✓ |

## MCQ Practice

**Q1:** What does `free(p)` do to `p`?
**A:** Nothing — `p` retains its value (becomes dangling)

**Q2:** Why does `free` not take size argument?
**A:** Bookkeeping metadata stored by `malloc` tracks size

**Q3:** What happens on `free(p+1)`?
**A:** Undefined behavior — no bookkeeping at that address

**Q4:** Difference between `malloc` and `calloc`?
**A:** `calloc` zeros memory; takes two args (count, size)

**Q4:** After `q = realloc(p, 100)`, if `q == NULL`?
**A:** Original `p` still valid; allocation failed

**Q5:** `struct S { int *p; }; S x, y; x.p = malloc(4); y = x; free(y.p);` — What is `x.p`?
**A:** Dangling pointer

**Q6:** How to safely copy a struct containing heap pointer?
**A:** Deep copy: allocate new memory for `y.p`, copy data
