# Unit 3: AVL Trees

## 7.1 Motivation

**Problem with BST:** Can become skewed (degenerate to list)
- Search: O(n) worst case, not O(log n)
- Need height-balanced tree

**Solution:** AVL Tree (Adelson-Velsky & Landis)
- Self-balancing BST
- **Balance Factor (BF):** BF = height(left) - height(right)
- **AVL Property:** For every node, BF ∈ {-1, 0, +1}
- If BF becomes +2 (left-heavy) or -2 (right-heavy) → rotation needed

---

## 7.2 Balance Factor

| BF | Meaning |
|----|---------|
| -1 | Right subtree 1 level taller |
| 0 | Perfectly balanced |
| +1 | Left subtree 1 level taller |
| +2 | **Left-heavy** → rotation needed |
| -2 | **Right-heavy** → rotation needed |

---

## 7.3 Four Rotation Cases

| Case | Path from Unbalanced Node | Rotation |
|------|---------------------------|----------|
| **LL** | Left → Left | Right rotation |
| **RR** | Right → Right | Left rotation |
| **LR** | Left → Right | Left + Right |
| **RL** | Right → Left | Right + Left |

**Memory Rule:**
- **Same direction** (LL, RR) → **Single rotation**
- **Opposite directions** (LR, RL) → **Double rotation**

---

## 7.4 Single Rotations

### LL Case (Right Rotation)
```
Before (insert 30, 20, 10):        After Right Rotation:
    30                                   20
   /                                       /  \
 20                                       10   30
/
10
```

### RR Case (Left Rotation)
```
Before (insert 10, 20, 30):        After Left Rotation:
10                                      20
 \                                       /  \
 20          ↓                         10   30
  \
  30
```

---

## 7.5 Double Rotations

### LR Case (Left Rotation + Right Rotation)
```
Insert 30, 10, 20:

Before:          Step 1: Left rotate 10       Step 2: Right rotate 30
    30                 30                          20
   /                    \                        /  \
 10                       20                    10   30
  \                     /
  20                   10
```

### RL Case (Right Rotation + Left Rotation)
```
Insert 10, 30, 20:

Before:          Step 1: Right rotate 30       Step 2: Left rotate 10
10                     10                          20
  \                      \                       /  \
  30                      20                    10   30
 /                        \
20                       30
```

## 7.6 Generalized Rotation Patterns

```
LL:        X              RR:        X
           / \                    / \
          Y  T4                  T1  Y
         / \                        / \
        Z  T3                      T2  Z
       / \                            / \
      T1 T2                          T3 T4
        ↓ Right                      ↓ Left
        Y                            Y
       / \                          / \
      Z   X                        X   Z
     / \ / \                      / \ / \
    T1 T2 T3 T4                  T1 T2 T3 T4

LR: X          X          Z          RL: X          X          Z
   / \  →     / \   →     / \          \  →       \   →     / \
  Y  T4      Z  T4       Y   X          Y            Z        X  Y
 / \        / \         / \ / \         / \          / \      / \ / \
T1 Z       Y  T3       T1 T2 T3 T4     T1 Z      T2  T3     T1 T2 T3 T4
  / \     / \
 T2 T3  T1 T2
```

## 7.7 Properties

| Property | Value |
|----------|-------|
| Height | O(log n) |
| Search | O(log n) |
| Insert | O(log n) |
| Delete | O(log n) |
| Rotations per insert | At most 1 (single or double) |

**Key Points:**
- Balancing doesn't alter BST property (inorder unchanged)
- Rotations change shape, not inorder listing
- More rotations than Red-Black trees but simpler logic
