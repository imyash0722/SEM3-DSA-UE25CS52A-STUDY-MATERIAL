# Unit 3: Splay Trees

## 8.1 Concept

A **Splay Tree** is a self-adjusting BST:
- **Whenever a node is accessed, move it to the root** (called **splaying**)
- **No balance factor** — no extra metadata (no height, no color bits)
- **Amortized O(log n)** — single operation can be O(n), but sequence of m operations = O(m log n)

### Key Features
| Feature | Description |
|---------|-------------|
| **No Extra Metadata** | No height, color, BF → saves memory |
| **Locality of Reference** | Recently accessed → root → subsequent lookups instant |
| **Dynamic Adaptation** | Tree morphs to actual access pattern |
| **Amortized Efficiency** | Worst case single op = O(n), but m ops = O(m log n) |

### Use Cases
- **Caches/Memory Allocation** — frequent items at root
- **Network Routers** — frequent IP lookups
- **Data Compression** — recurring patterns

## 8.2 Three Splay Cases

| Case | Condition | Action |
|------|-----------|--------|
| **Zig** | Node is child of root | Single rotation |
| **Zig-Zig** | Node & parent on same side | Two rotations (same direction) |
| **Zig-Zag** | Node & parent on opposite sides | Two rotations (opposite directions) |

**Memory Rule:**
- **Same direction** → Zig-Zig
- **Opposite direction** → Zig-Zag
- **One level from root** → Zig

---

## 8.3 Case Details

### Zig (Node is child of root)
```
Access 30:           Access 70:
   50                    50
  /                        \
30                        70
 ↓ Right rotate         ↓ Left rotate
30                        70
 \                        /
 50                      50
```

### Zig-Zig (Same side — LL or RR)
```
Left-Left (LL):
    50                30                20
   /        →        /  \         →       \
 30                   20  50              30
/                           →            /  \
20                         20           10   50
                                      \
                                      10

Right-Right (RR):
20                          30                  50
 \                          /  \                /
 30       →  two left rots  20   50    →       30
   \                                           /  \
   50                                         20   40
```

### Zig-Zag (Opposite sides — LR or RL)
```
Left-Right (LR):
    50                50                30
   /        →       /       →           /  \
 20                 30                20   50
  \                /                  /    \
  30              20                 20     50
```
1. First: Rotate parent (20) toward child (left rotate)
2. Then: Rotate grandparent (50) toward parent (right rotate)

**Right-Left (RL):**
```
    50                50                30
     \        →       \        →         /  \
     20               30               50   20
    /                /                 \     \
   30              20                  40    20
```

## 8.4 Splay Example Traces

### Example 1: Search for 20
```
Initial:              Path: 50→30→20 (Zig-Zig)
    50
   /  \
 30    70
/  \
20  40

After splaying 20:
      20
       \
        30
         \
          50
         /  \
       40    70
```
**Key point:** 20 (accessed) now at root

### Example 2: Then search for 60
```
Current:            Path: 20→30→50→70→60 (Zig-Zag at 70→60)
    20
     \
      30
       \
        50
       /  \
     40    70
           /  \
         60    80

After splaying 60:
         60
        /   \
      20     70
       \      \
       30     80
         \
         50
        /
      40
```
**Key point:** Every access modifies the tree!

## 8.5 Rotation Summary Table

| Configuration | Splay Operation |
|---------------|-----------------|
| Node is child of root | Zig (1 rotation) |
| Left-Left | Zig-Zig (2 right rotations) |
| Right-Right | Zig-Zig (2 left rotations) |
| Left-Right | Zig-Zag (left then right) |
| Right-Left | Zig-Zag (right then left) |
