Unit 1: Structures¶

4.1 Concept¶

Structure: Named collection of related items (fields/members) — not necessarily same type.

Analogy: Backpack containing laptop, books, pens, water bottle — different items grouped under one name.

4.2 Declaration and Definition¶

Structure Type Declaration:¶

struct student
{
    int rnum;
    char name[20];
    int marks;
};
- Declares type struct student - No memory allocated (only tells compiler layout) - Ends with ; (required) - Should go in header file (needed by client and implementor)

Creating Variables:¶

struct student s1;        // Stack allocation
struct student *p = &s1;  // Pointer to structure

Accessing Fields:¶

Syntax Use Case
s1.marks = 78; Direct (. operator)
(*p).marks Via pointer (parentheses needed!)
p->marks Via pointer (arrow operator, preferred)

4.3 Structure Characteristics¶

Property Description
Heterogeneous Fields can be different types
Named fields Access by name, not index
Fixed offsets Determined at compile time
Random access O(1) field access
No pointer decay Structure variable ≠ pointer (unlike arrays)
Assignment compatible Memberwise copy (s2 = s1)
Contains arrays? Yes, assignment still works (memberwise copy)

4.4 Structure Layout, Padding, and Alignment¶

The Problem:¶

struct test1 {
    char j;   // 1 byte
    int i;    // 4 bytes
};
Expected: 5 bytes
Actual: Often 8 bytes (implementation-dependent)

Why? Alignment and Padding¶

  • Each type has alignment requirement (e.g., int = 4-byte boundary)
  • Compiler inserts padding bytes between fields for alignment
  • Trade-off: Speed (aligned access) vs Space (no padding)

Example Layouts:¶

Without padding (packed):
Offset 0: char j (1 byte)
Offset 1: int i (4 bytes)  ← misaligned!
Total: 5 bytes

With alignment (typical):
Offset 0: char j (1 byte)
Offset 1-3: padding (3 bytes)
Offset 4: int i (4 bytes)  ← aligned to 4-byte boundary
Total: 8 bytes

Controlling Packing:¶

#pragma pack(1)    // Align to 1-byte boundary (no padding)
struct test1 { char j; int i; };
#pragma pack()     // Restore default

// Check sizes with different pack values

Note: #pragma is compiler-specific, not portable.

4.5 Initialization¶

Uninitialized (garbage):¶

struct student s1;
printf("%d %s %d", s1.rnum, s1.name, s1.marks);  // Junk values

Full Initialization (order must match):¶

struct student s2 = {23, "pes", 99};

Partial Initialization (rest = 0):¶

struct student s3 = {23, "pes"};  // marks = 0

Designated Initialization (C99):¶

struct student s5 = {.name = "pes", .marks = 45};  // rnum = 0

4.6 Copying and Comparison¶

Memberwise Copy:¶

struct test1 { int i; char ch; };
struct test1 t1 = {23, 'w'};
struct test1 t2 = t1;  // Copy on initialization
t2 = t1;               // Copy on assignment
- t2 is independent copy (no shared memory) - Works even with array members

Comparison:¶

// No direct == operator for structs!
if (t1.i == t2.i && t1.ch == t2.ch)
    printf("equal");

4.7 Parameter Passing¶

Pass by Value (Default - makes copy):¶

void f1(struct test t) {
    strcpy(t.a, "pqrstuv");  // Modifies LOCAL copy
}
struct test t1 = {20, "xyz", 78.5f};
f1(t1);  // t1 unchanged!

Pass by Reference (Modify caller's):¶

void f2(struct test *p) {
    strcpy(p->a, "pqr");  // Modifies ORIGINAL
}
f2(&t1);  // t1 changed!

Best Practices:¶

Scenario Recommendation
Modify struct Pass struct test*
Read-only Pass const struct test*
Avoid Pass by value (slow, copies everything, problematic with pointers)

Const Correctness:¶

void f3(const struct test *p) {
    // strcpy(p->a, "pqr");  // Compile ERROR
    printf("%s\n", p->a);    // OK: read-only
}
f3(&t1);  // Safe

4.8 Returning Structures¶

Return by Value:¶

struct test f1(struct test t) {
    strcpy(t.a, "pqrstuv");
    return t;  // Returned to temporary, then copied to caller
}

Return Pointer (DANGER if local):¶

struct test* f_bad() {
    struct test local;
    return &local;  // DANGLING POINTER!
}

struct test* f_good() {
    static struct test global;  // Or malloc'd
    return &global;  // OK
}

4.9 typedef: Creating Abstraction¶

Problem:¶

Client sees struct student — knows internal structure.

Solution: Opaque Type with typedef¶

struct student {
    int rnum;
    char name[20];
    int marks;
};

typedef struct student student_t;  // New type name

Usage:¶

student_t s1;  // Client uses 'student_t', not 'struct student'
// Implementation can change to array/struct-of-structs without breaking client

Convention: Use _t suffix for typedef names.

Summary Table¶

Operation Syntax Notes
Declare type struct Name { ... }; In header file
Create variable struct Name var; Stack allocation
Pointer to struct struct Name *p = &var;
Access field (direct) var.field . operator
Access field (pointer) p->field -> operator (preferred)
Initialize struct Name v = {val1, val2}; Order matters
Designated init struct Name v = {.field = val}; C99
Copy v2 = v1; Memberwise
Compare Manual field-by-field No ==
Pass by value void f(struct Name v) Copies entire struct
Pass by ref (modify) void f(struct Name *v) Use ->
Pass by ref (const) void f(const struct Name *v) Read-only
Return value struct Name f() Memberwise copy
Return ptr struct Name* f() Must not be local!
Typedef typedef struct Name Name_t; Abstraction

MCQ Practice¶

Q1: What is the size of struct { char c; int i; } on typical 32-bit system? A: 8 bytes (padding after char for int alignment)

Q2: What does #pragma pack(1) do? A: Disables padding; aligns all fields to 1-byte boundary

Q3: How to initialize only specific fields? A: Designated initializer: struct S s = {.field = value};

Q4: Can you write if (s1 == s2) for structs? A: No! Must compare fields manually.

Q4: Best way to pass large struct to function for reading? A: const struct Name *p

Q5: struct S { int *p; }; S x, y; x.p = malloc(4); y = x; free(y.p); — What is x.p? A: Dangling pointer
