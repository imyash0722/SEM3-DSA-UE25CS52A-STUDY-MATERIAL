Applications using Stack
Evaluation of Expression  : 
It is so complicated to evaluate an expression. We had something called BODMAS rule.   B — 
Brackets (solve things inside ( ), [ ], { } first)
  O — Orders (powers, square roots, or indices)
  D — Division
  M — Multiplication
  A — Addition
  S — Subtraction.
It was very simple. But in programming languages like ‘C’, we have multiple levels of precedence. 
So also we have variation of associative rules. Nesting of parentheses adds one more level of 
complication.
Can we have expressions which can be evaluated as soon as the operator is encountered?
In the normal way of writing, we write the operator between the operands. These are some simple 
examples. 
3 + 4
4 * 5 + 6
4 + 5 * 6
5 * 6 + 7 * 8 
These are called infix expressions – the operators are between the operands.
Can we have expressions where the operator appears after the operands?
Let us relook at the expressions above.
3 4 +
4 5 * 6 +
4 5 6 * +
5 6 * 7 8 * +
These are called postfix expressions – the operators are after the operands.

In postfix expressions, all operators at the same level of precedence. All operators are left 
associative. We can create a stack of operands. As soon as an operator is encountered, we pop the 
operands from the stack, evaluate the expression based on the operator, push the result back into 
the stack. When the expression is completely processed, the stack should have a single value which 
is the result. 
We will discuss how to convert an infix expression to postfix expression later in this document.
We will try to understand how stack is used to evaluate each of the expressions above.

Algorithm for conversion of infix to postfix:
We have discussed the advantage of having an expression in postfix. The evaluation becomes 
simple. There is no hierarchy. This also implies that there are no parentheses.
How do we convert an expression in infix to an expression in postfix? To do this, we use a stack of 
operators. 
Let us discuss a few simple examples before we go through the algorithm in detail.
Example 1 :
3 + 4 
Whenever we get operands, we  just output them to the postfix expression.
When we encounter an operator, if the stack is empty push the operator on to the stack.
When all the operands are processed, pop from the stack into the postfix expression until the stack 
becomes empty.
Output 3; push + ; output 4; pop + : 
Postfix expression : 3 4 + 
Example 2 :
4 * 5 + 6
As per the earlier example, we do the following steps.
Output 4; push *; output 5 
We encounter + in the string and we have * on the stack. Since * has a higher precedence 
compared to +, 
pop * and push +.
Output 6
Pop the stack until empty
Pop +
Postfix expression : 4 5 * 6 +

Example 5 :
What if the infix expression has parentheses? There are no parentheses in postfix expression as 
there is no precedence. 
We treat the parentheses differently. We want to always push the left parenthesis onto the stack. 
We will  give left parenthesis a very high precedence value in the string so that it always gets 
pushed in.   Once it is in the stack, we want all other operators to get pushed in until the right 
parenthesis is encountered. So, we associate a very low precedence value to the left parenthesis 
once it is in the stack.
When we encounter a right parenthesis, we pop all operators until we encounter left parenthesis 
on the stack to the output. We then pop the left parenthesis out.
