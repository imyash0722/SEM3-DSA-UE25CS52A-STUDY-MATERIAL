Tree
A few points:
So far, we have said that the tree is a non linear data structure.  A tree is an acyclic, connected graph. A 
tree of n nodes has n -1 branches or edges. If we add an edge, a cycle is formed. If we remove an edge, 
the connectivity between every pair of nodes is lost.
A general tree is defined as 
a) Either empty or
b) Has a root followed by number of subtrees.
Some of the terms we use with the tree are:
Root, nodes, internal nodes, leaves, branches, path, ancestor, descendant 
Parent, child, grand parent, grandchild, siblings, uncle
Height, depth, level.
Degree of a node.

Traversals:
1. Inorder traversal of a binary tree:
We can visit all the components in an array or a list from one end to another. It is not possible to 
do so in case of a tree. One of the ways of visiting all the components in a binary tree is to visit 
the left subtree somehow and then the root and then the right subtree somehow. If the tree is

----------------------------------------

===== Page 5 =====

empty, there is nothing to visit. As the left and the right subtrees are trees, we could apply this 
logic recursively.
Before visiting A, we visit left sub tree of A – that is the subtree B.
Before visiting B, we visit left sub tree of B – that is the subtree D.
Left sub tree of D is empty. So visit D.
Right sub tree of D is empty. So the sub tree D has been visited.
Left sub tree of B has been visited. So visit B.
Now visit the right sub tree of B. 
Next we visit E.
Now, the left sub tree of A is visited. So visit A and then its right subtree.
This results in visit C  and then visit F.
So the traversal of this tree will result in :
D B E A C F

Implementation of Binary Search Tree:
To start with, we will make a simple example of binary trees. We will use a special binary tree 
called binary search tree.
In a binary search tree, every component has a key. The components are arranged based on the 
key. 
If the tree is empty, the component is put at the root. 
Otherwise, if the key in the component at the root is higher than the key in the new component, 
we will insert in the left subtree.
Otherwise, we will in the right subtree.
You will observe that the insertion always happens as a leaf.
One of the implementations will be as follows.
The tree has a root. This is like a list having a head.
The root points to a node structure. 
The node structure has a component – called key – in this example.
Apart from that, it has two pointers – which point to the left and the right sub trees.

Search for a key in a binary search tree:
A binary search tree is organized based on a predicate applied at the root. We use this 
predicate while inserting as well as searching. 
While inserting if the root is empty, the node with the key is made the root.
Otherwise, we compare the key with the key at the root. If the key is less than the key at the 
root, we insert in the left subtree otherwise in the right subtree.
There are two aspects to searching in a tree. 
-
How to search?
-
What to return?
If the tree is empty, the key is not found. 
If the key matches the key at the root, the key is found at the root. 
Otherwise if key is less than the key at the root, we search the left subtree recursively 
Else search the right subtree recursively.

How to store a tree and how to restore a tree?
If a list has to be stored, we could traverse and right the components to a file.  We can restore the list by 
reading the components from the file and attaching them at the end of the list.
A list is a linear data structure. So we cannot do the way we have stated above.
A tree is non linear. A single traversal will not define the tree completely. 
For example, if a tree of 3 nodes has an inorder traversal A  B C, there are 5 possible trees which can 
produce the same inorder traversal.
An inorder and a postorder traversals of a tree uniquely defines a tree. Given the two traversals, we can 
reconstruct the tree.
Let us take an example to illustrate. 
                         A
                       /   \
                      B     C
                     / \   / \
                    D   E F   G
                       /             \
                      H           I
                               /
                              J
There are exactly 10 nodes:

----------------------------------------

===== Page 22 =====

A, B, C, D, E, F, G, H, I, J
The inorder traversal of the tree : D B H E A F C G J I
The post order traversal of the tree : D H E B F J I G C A
To reconstruct the tree, traverse the post order traversal from the right. The last node A has to be the 
root of the whole tree. Therefore, A is the root and A divides the inorder traversal into two parts. All 
nodes to the left of A are in left subtree of A and all the nodes to the right of A in the right subtree.
So, we know the root of the tree.
Next to the right of A in postorder traversal is C. C is to the right of A in inorder traversal. C is the root of 
the right subtree of A.
This way we may continue to build the whole tree.

Expression Tree
A few points:
In this chapter, we will examine how a postfix expression can be converted to an expression tree where 
the leaves are operands and internal nodes are operators. We will also examine how we can find the 
value of such an expression. 
Algorithm:
Input : an expression in postfix. For simplicity, the operands are assumed to be single digits.
Process : construct an expression tree
Output: find the value of the expression 
Phase 1:
Construct the expression tree:
Data structure used: stack of tree nodes
Scan the input left to right 
If operand, create a tree node and push it to a stack of tree nodes.
If operator, pop two tree nodes from the stack, create a new tree node with the operator as the key.
Attach the popped nodes as subtrees of the new node. 
Push the new node into the stack.
Phase 2 :
Evaluate the expression tree:
Stack should have one and only one tree node.
On this tree, do the evaluation.
If the node is a leaf, return the operand.
Else 
     Evaluate the left subtree
     Evaluate the right subtree
     Apply the operator of this node on these two results
Details of the interface and the implementation:
Stack:
We are using an array implementation of the stack. Each element of the stack is a  node which has two 
self referential members left_ and right_ standing for left and right subtrees.
It has a key field of char type.

Threaded binary tree:
In a tree of n nodes, there are only n-1 edges or branches. In a node based implementation, each node 
has 2 pointers. We require only n-1 pointers to point to nodes – these are called structural pointers. So,

pointer, make it point to the predecessor? Similarly, instead of grounding the right pointer, can we make 
it point to the successor? Such a pointer is called a thresad.
How do we make out whether the pointer is a structural pointer or a thread?
To facilitate this, we may require two bit fields. 
Check the structure of the node in the header file : tree.h in the folder threaded.
Lthread is 1 if left is thread and a structural pointer.  Similarly, rthread is 1 if right is a thread and not a 
structural pointer. Otherwise, they will be 0.

Heap
A few points:
There are many words in Computer Science which have different meanings depending on the context. 
Already we have observed that thread in Operating Systems stands for a unit of execution whereas 
threaded tree makes the NULL structural pointers point to its successor or predecessor making iterative 
functions possible for a particular order of traversal.
Similarly, the word heap has 2 meanings. Heap in memory management refers to a part of the memory 
supporting allocation and deallocation of memory dynamically.
In data structure, a heap refers to a special type of binary tree. It is not a search tree.
There are two kinds of heaps – called maxheap and minheap.
In our discussion, we will discuss the maxheap. The interface and the implementation of minheap will be 
similar – we have to change the comparison operator from “greater than” to “less than”.
A heap(maxheap) is a tree with two special properties.
1. Complete binary tree:
The nodes are filled up at each level.
At the bottom most level, leftmost nodes are filled up.
2. Parental dominance:
The key at the root is greater than the keys of its subtrees recursively.
Three diagrams in the next page illustrate the properties of the heap tree.
The first one is a heap. The root has the highest value and keys at the roots of the subtree are less than 
that of the root. There is no ordering of keys at the left and the right subtrees. This must be true 
recursively. Evidently, leaves are always heaps. Also, observe that the first 3 levels are totally filled up. In 
the last level, the leftmost nodes are filled up.

not satisfy parental dominance. So, this is not a heap.
In the third example, the second level(counting from 0) is not completely filled. The left subtree 
of node with key 80 is missing. So this is not a heap.  This tree has 7 nodes.

AVL Trees
A few points:
A binary search tree allows us to discard one of the subtrees while searching. Based on the key 
comparison at the root, we could discard the left subtree or the right subtree. Would that mean that the 
number of comparisons in the worst case will be log(n, 2) where n is the number of nodes in the tree?
The answer is NO. It is possible that the tree could become skewed. The tree could degenerate into a 
list. In such a case, the number of comparisons while searching will be proportional to the number of 
elements and will not become logarithmic. 
How do we make the tree have the same depth – at most with a difference of 1 – no matter in which 
direction we move from the root?
This leads to a concept called Height Balanced Binary Search Trees. AVL tree is one of them.
AVL trees:
This tree was invented by  two Russian Mathematicians : Adelson-Velsky and Landis.
An AVL tree is a self-balancing Binary Search Tree (BST).
AVL stands for Adelson-Velsky and Landis, the two researchers who introduced the tree.
The key property is:
For every node, the heights of its left and right subtrees differ by at most 1.
Balance Factor
For every node: h: stands for the height

For an AVL tree, the balance factor must be:

Splay Trees
A few points:
A Splay Tree is a self-adjusting Binary Search Tree (BST).
Whenever a node is accessed, move that node to the root.
This operation is called splaying.
There is no concept of balance factor.
Features:

No Extra Metadata: They require no balance accounting data (like color bits in red-
black trees or height numbers in AVL trees), saving memory. 

Locality of Reference: If we access a piece of data once, it moves to the top, making 
subsequent lookups of the same data instantaneous. 

Efficiency: While a single worst-case operation can take time proportional to the number 
of elements, a sequence of m operations is guaranteed to run in time proportional to m * 
log(n, 2).

Dynamic Adaptation: The tree structure continuously morphs to fit the actual access 
pattern of the workload rather than enforcing a rigid shape. 
Uses:

Caches and Memory Allocation: Great for systems where a small subset of data is 
requested repeatedly.

Network Routers: Used to quickly look up frequently matched IP addresses.

Data Compression: Ideal for algorithms that exploit recurring patterns in data streams.
The first diagram in the next page illustrate the three basic operations : Zig-Zig, Zig-zag and Zig. 
We shall discuss them in detail.

Euler’s solution is simple. If we start from a vertex and end there, we require two edges. We enter 
vertex and leave it each time we require two edges. So, only if the degree of each vertex is even, it is 
possible to traverse a graph without repeating an edge.
A graph is said to be Eulerian if it supports the traversal of edges once and only once and come back to 
the starting point. The necessary and sufficient condition is that the degree of each node should be 
even.
What if want to visit each vertex only once and come back to the starting point? This is called 
Hamiltonian cycle. Even though this appears similar to Euler cycle, till today we do not have a simple 
solution to determine whether a Hamiltonian circuit exists for a given graph.

Graph representation
A. Adjacency matrix
An adjacency matrix A is a V × V array. For an unweighted graph, A[i][j] is 1 when an edge exists 
and 0 otherwise. For an undirected graph, the matrix is symmetric. The 8-vertex example 
requires an 8 × 8 matrix.
Space: O(V²). Checking whether an edge exists takes O(1) time.
The space required is proportional to the square of the number of vertices.
The time to check whether there is an edge between the vertices i and j requires constant time – 
does not depend on the number of vertices or number of edges.
