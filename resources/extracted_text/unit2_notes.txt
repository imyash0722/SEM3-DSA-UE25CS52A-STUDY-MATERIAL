Circular List
We have seen some video clippings restart from the beginning when the end is reached. There are music 
players which repeat the songs from the playlist. These are basically manifestations of the data structure 
called circular list.
As the name itself indicates, it is a list where the nodes form a cycle. We can loosely say that the last 
node is connected back to the first. At any given point in time, we will have a pointer to one of the nodes 
in the circular list.
It is also possible that the circular list could have two pointers in each node – one points to the next and 
the other points to the previous – thus forming a doubly linked circular list. These types of lists are 
extremely common in operating systems.
The interface of a circlular linked list is same as that of a singly linked list. 
It supports the following operations.

Initialize the list

Deinitalize the list 

Insert before/after a node 

Delete the node following the current node in the list

Traverse 

Search for a key
The structure of the circular list is same as that of a singly linked list.
head_ : this will point to one of the nodes. We may want to give some other name for it.
The node structure is same as the one we have used in singly linked list.

Display
Normally, we do not prefer do-while loop. We prefer top tested loops than bottom tested loops.
But, in case of circular lists, do-while loop is preferred. We start from the head_ node, go to the next 
one repeatedly until the head_ is reached again.
void disp_list(clist_t* ptr_clist)
{
    node_t *pres = ptr_clist->head_;
    if (pres == NULL) {
        printf("List is empty\n");
        return;
    }
    node_t* temp = pres;
    printf("Circular List: ");
    do {
        printf("%d ", temp->key_);
        temp = temp->next_;
    } while (temp != pres);
    printf("\n");
}

Josephus Problem:
This problem has been stated in literature in number of ways. This is one of the versions.
Josephus Problem asks you to find the last remaining survivor from n people standing in a circle. 
Counting begins at a specific person and moves around the circle in a fixed direction. In each step, k-1 
people are skipped, and the k-th person is removed. The process repeats until only one person is left. 
The steps involved in solving this problem are:
1. n people are numbered from 1 to n in order and are placed in a circle
2. Starting from a designated start point, we count to kth person.
3. The kth person is eliminated
4. Counting and elimination steps are repeated until a single person is left
5. Original number of that person is the solution.
Let's take a small example:

n = 7 people 


Doubly Linked List
A doubly linked list is a list which allows us to travel to the next node or the previous node from the 
current node. To facilitate this, every node apart from the component has two pointers – one to the 
next normally called next and the other called prev for previous. 
The interface of a doubly linked list is same as that of a singly linked list. 
It supports the following operations.

Initialize the list

Deinitalize the list 

Insert anywhere in the list 

Delete anywhere in the list

Traverse 

Search for a key
The doubly linked list structure will have two pointers: 
head_ : this will point to the first node.
tail_ : this will point to the last node.
struct DLL {
node_t *head_;
node_t *tail_;
};
typedef struct DLL dll_t;
The node structure will also have two pointers – traditionally called prev and next.

In case of a singly linked list, we had to have two pointers, one following the other as we could not 
move back in the list. That restriction no more exists in a doubly linked list. To insert a node temp 
before the current node pres, we could do the following changes.
temp->next_ = pres;  temp->prev_ = pres->prev_;
pres->prev_->next_ = temp; pres->prev_ = temp;
You may observe that we make 4 changes while inserting.
The above code works only if we are inserting in the middle. What if we insert in 
-
An empty list : both head_ and tail_ of the DLL should be changed
-
In the beginning : head_ of the DLL has to change
-
At the end : tail_ of the DLL has to change

Traverse :
We can traverse forward or backward as we have links in both the directions.
Why doubly linked lists?
A singly linked list can do whatever a doubly linked list can do. Then, what do we gain by creating a 
doubly linked list?
As we can traverse in both directions, insertion, deletion become easier. 
We use more space – extra pointer in each node. We gain in time.
This is a classical example of Time Space Trade Off.

Let us compare the performance of singly and doubly linked lists in terms of number of steps required 
for each of the following operations in the worst case. Assume that the list has n nodes. 
-
Move forward :  singly linked list : 1 step; doubly linked list : 1 step : no difference 
-
Move back : singly linked list : n step; doubly linked list : 1 step : 
-
Insert before a node : singly linked list : 1 step; doubly linked list : 1 step : 
-
Delete a node : singly linked list : 1 step; doubly linked list : 1 step : 
-
Searching for a key : singly linked list : n step; doubly linked list : n step : 
A doubly linked list does NOT make searching faster.
The advantage is bidirectional traversal and easier local insertion/deletion.

Queue
So far, we have learnt the data structures list, stack, circular list. We have observed that these are  all 
abstract data types supporting a well-defined interface. We have also observed that each of these 
abstract data types could have different implementations. These data structures are found to be useful 
in different applications based on their interfaces.
Consider the case of printing a few files on a printer. We can fire the print command on many files all at 
once. How would the printer handle this? Would the files get mixed up? Not at all. The files are printed 
in the order in which they arrive at the printer. Whichever comes first will be printed first. The printer 
follows “First Come First Served” principle. To support this behaviour, the files are put in a queue. The 
files are serviced from the front and are attached at the rear.
Queue is a data structure which has two ends – normally called the rear and the front. The components 
are added at the rear and removed from the front. We say that the queue exhibits the behaviour  - FIFO 
– First In First Out.
Interface of the queue:
Apart from initialization and deinitialization, the queue supports the following operations.
initialize()
Create an empty queue
enqueue(x)
Insert x at the rear
dequeue()
Remove the element at the front
front() / peek()
Examine the front element
isEmpty()
Check whether the queue is empty
isFull()
Check whether the queue is full, for 
bounded implementations
destroy() / deinitialize()
Release resources

Implementation : We can implement the queue in different ways. We will discuss “implementing the 
queue using a list” in this section. We will discuss “implementing the queue using an array in the next 
section”.
The queue shall have the following structure. It has two pointers referred to as front_ and rear_.
struct queue
{
    node_t* front_;
    node_t* rear_;
};
typedef struct queue queue_t;
The node shall have the component and a pointer to a node – it is a classical self-referential structure. 
struct node
{
    int key_;
    struct node* next_;
};
typedef struct node node_t;
For illustration purpose, the component type is chosen as an int. 
Design consideration : How to link the nodes?
The two major operations on a queue are :
Adding at the rear : enqueue 
Removing from the front : dequeue.
How to support these operations efficiently?

===== Page 14 =====

Design 1 :
One possible arrangement could be as follows. 
Rear of the queue will point to the last node. The last node will point to the node which came before 
that. This in turn points to the node which came before that and so on. The front will point to the first 
node.
You will observe that enqueue will require a few operations. Create a node. Populate it. Make the 
pointer field take the value of rear of the queue. Change rear to point to the new node created.
So far so fine.
How about removing the first node from the front? This would require that the front should point to the 
node after the first node. But the pointer field in that node is grounded. As this is a singly linked data 
structure, we cannot move back. The only way we can satisfy this is by travelling all the way from the 
rear to the front. So, deque would take as many operations as the number of nodes in the queue. This is 
not acceptable. 
Design 2 :
Let the node pointed to by the front of the queue point to the next node. Each node shall point to the 
node which came later. The rear of the queue shall point to the last node whose pointer field is 
grounded.
Enqueue requires that we create a node, populate it, change the pointer field of the node pointed to by 
rear to this new node, ground the pointer field in the new node, change rear to point to this new node.
This requires just a few operations. So fine.
Dequeue requires that we change the front to take the pointer in the first node so that it points to the 
next node. 
This also requires just a few operations. So fine.
So, in out design each node will point to the node which came next.

1. Empty queue : We cannot remove an element from an empty queue. We will give a message to

o

o
Copy the component in this node to a local variable say result

is grounded. What about the rear?
When there is only one node in the queue and it is dequeued, then the rear also will change!

#define MAXSIZE 5
struct queue 
{
int key_[MAXSIZE];
int front_;
int rear_;
};
typedef struct queue queue_t;
For illustration purpose, the component type is chosen as an int. 
Design consideration : How to handle the indices front and rear in enqueue and dequeue? 
a) Incrementing indices correctly
Initially both these could be same – some valid index. Could be zero. On enqueue we should 
increment the rear and deque we should increment the front.
The valid indices can be anything in between 0 and MAXSIZE – 1. If we keep incrementing, the index 
can go outside the array boundary. Or if we were to say that the queue is full when the rear reaches 
MAXSIZE, it could be wrong if there have been a few deque operations.
To avoid the index going outside the array bounds and to avoid saying that the queue is full when 
some elements have been freed by deque, we will use modulo arithmetic.
To increment the index say i, we shall say 
i = (i + 1) % MAXSIZE
b) Checking for queue empty and queue full 
If the rear catches the front, queue is full. 
If the front catches the rear, queue is empty.
These could be fairly complicated conditions.
Can we make that simple by using the same condition for both queue full and queue empty?
We can provided we waste one location. 
But this might be checked at different points in time enqueue and dequeue. 
We shall discuss at length in these operations.

So far, we have learnt the data structures list, stack, circular list and queue. We have observed that

A priority queue is an abstract data type in which each element is associated with a priority.
Unlike an ordinary queue, where elements are removed according to FIFO (First-In, First-Out) order, a

the priority. Or lower the numeric value could mean higher priority. In Unix, the latter concept is 
followed. You may know that there is a command called nice using which you can reduce the priority of 
your process – you can be nice to others!
In our examples, we will assume that higher the numeric value, higher the priority.
What is the rationale behind this? Let us consider a couple of examples.
The patients wait in a queue to consult a doctor. But what if a patient becomes critically ill? Should not 
that patient get immediate attention?
Several processes could be running on an operating system. A few of them may have to respond in real 
time. Should not these get preference over others?

We must find the node with the highest priority. If there are mode nodes with the same highest priority, 
we should select the job which came first. So, such a node will be closed to the front than the other 
nodes with the same priority.

There are two parts in the algorithm. 
The first is to find the position of the node with the maximum priority. We traverse the normal way.. We

change. If it is the only node, the rear has to change. Otherwise we should make next of max_prev take 
the value of next of max_pres. Then release the max_pres node. Then return the job previously 
captured.

Enque :
We want to arrange the nodes such a way that the nodes with the highest priority are at the end of the 
array. We also want the nodes with some priority which came earlier to be towards higher indices 
compared to the ones which came later with the same priority.
Enque is simple. Remove the last node in the array.
If the array is full, the program is exited.
Otherwise insert the new node at the right position. The nodes are being arranged in non-decreasing 
order of priority. We basically implement a very famous algorithm called insert. This is used in a sorting 
algorithm called insertionsort.
We traverse right to left and stop as soon as the right position is found to insert. As we know that we 
have to insert and make space for a new node, we keep shifting to the right every time we enter the 
loop.
Once we are out of the loop, we assign the new node to the right position.

void enque(queue_t *ptr_queue, job_t *ptr_job)
{
if(! is_full(ptr_queue))
{
int n = ptr_queue->n_;
int i = n - 1;
int priority = get_priority(ptr_job);
while(i >= 0 && 
get_priority(&ptr_queue->key_[i]) >= priority)
{
ptr_queue->key_[i + 1] = ptr_queue->key_[i];
--i;
}
ptr_queue->key_[i + 1] = *ptr_job;
++ptr_queue->n_;
}
else 
{
printf("queue full; cannot push\n"); 
exit(1);
}
}

Priority Queue : Different implementations
A priority queue is an abstract data type in which each element is associated with a priority.
Unlike an ordinary queue, where elements are removed according to FIFO (First-In, First-Out) order, a 
priority queue removes the component with the highest priority first.
A priority is a number associated with each component. Higher the numeric value, could mean higher 
the priority. Or lower the numeric value could mean higher priority. 
In our examples, we will assume that higher the numeric value, higher the priority.
Let us relook at the interface of the priority queue before discussing the implementation using 
unordered list.

The interface of a priority queue is same as that of queue. Component x would have a priority associated

Priority Queue : unordered array implementation
A priority queue is an abstract data type in which each element is associated with a priority.
Unlike an ordinary queue, where elements are removed according to FIFO (First-In, First-Out) order, a 
priority queue removes the component with the highest priority first.
A priority is a number associated with each component. Higher the numeric value, could mean higher 
the priority. Or lower the numeric value could mean higher priority. 
In our examples, we will assume that higher the numeric value, higher the priority.
Let us relook at the interface of the priority queue before discussing the implementation using 
unordered list.
Interface of the priority queue:
The interface of a priority queue is same as that of queue. Component x would have a priority associated 
with it.
initialize()
deinitialize()
Create an empty queue
Make the queue empty
enqueue(x)
Insert x
We may add in number of ways. This in 
turn would affect dequeue
dequeue()
Remove the element with the highest 
priority. This in turn depends how 
enqueue operation was done
isEmpty()
Check whether the queue is empty
isFull()
Check whether the queue is full, for 
bounded implementations

A few points:
So far in this course, we have discussed that a data structure has number of components. Each data 
structure is a type – called Abstract Data Type and each data structure supports a set of operations 
meaning for that data structure.
Each component knows about itself very strongly. It is cohesive. It does not know in which data structure 
it will be put. 
Each data structure knows little about the component it contains. Whenever it requires any services 
from the component, it will delegate the function to that of the component. It does not probe inside the 
component to see what it contains. So, the data structure is also cohesive.
There is not much of dependency between the data structure and the component. They are not coupled. 
By this way we realize one of the requirements of software development – high cohesion and low 
coupling.
We have discussed a few data structures like list, stack, queue, doubly linked list, circular queue. The 
components of all these data structures are in a line – they are linear. Even though the doubly linked list 
has two pointers in each node, they still are in a line. These data structures are called linear data

Inorder traversal of a binary tree:
We can visit all the components in an array or a list from one end to another. It is not possible to 
do so in case of a tree. One of the ways of visiting all the components in a binary tree is to visit 
the left subtree somehow and then the root and then the right subtree somehow. If the tree is 
empty, there is nothing to visit. As the left and the right subtrees are trees, we could apply this 
logic recursively.
Before visiting A, we visit left sub tree of A – that is the subtree B.
Before visiting B, we visit left sub tree of B – that is the subtree D.
Left sub tree of D is empty. So visit D.
Right sub tree of D is empty. So the sub tree D has been visited.
Left sub tree of B has been visited. So visit B.
Now visit the right sub tree of B. 
Next we visit E.
Now, the left sub tree of A is visited. So visit A and then its right subtree.
This results in visit C  and then visit F.
So the traversal of this tree will result in :
D B E A C F

A general tree might have nodes with any number of children. Processing such a tree is difficult. 
But, if we can represent the general tree as a binary tree, then processing becomes easy. 
A binary tree can represent only two properties – one for the left branch and one for the right 
branch. If we can match this to two properties of a general tree, then we can represent any 
general tree as a binary tree.




Sibling a node in a general tree becomes the right child of that node or attached to the right

A few points:
Deque is a data structure which stands for double ended queue. It is pronounced as deck. 
This data structure has two ends and at each end, supports addition as well as deletion. 
It is normally implemented as a doubly linked list. Otherwise at least one of the 4 operations would be

In fact, the doubly linked list that we implemented with limited interface is a deque.
Once a data structure has been implemented, we do not directly modify it. We extend it by either 
inheritance in an object oriented language or by composition. As ‘C’ is not an object oriented language, 
we will limit our discussion to extending the use of data structure by composition.
We shall implement a stack using deque. We do not want to reinvent wheels. If already a data structure 
provides the required interface and implementation, we match out interface to that of the existing data 
structure.
