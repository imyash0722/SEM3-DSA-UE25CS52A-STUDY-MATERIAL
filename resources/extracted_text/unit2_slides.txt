Circular List : concept

• This is a list

• The last node points to the first

             • Have a pointer to one of the nodes

             • first and last are not very meaningful

• When the elements form a cycle or need to be processed repeatedly,

                           the last element should naturally lead back to the first.

Circular List: implementation
• Initialize / Deinitialize the list
    • Initialize : Make head_ NULL
    • Deinitialize : Traverse and remove nodes until back to the first node;
           Remove that node; ground the head_.
• Insert after/before the first node
    • Insertion is exactly the same
    • Modify the head_ suitably
• Delete after the first node
• Traverse
    • Prefer a do…while loop
    • Stop when the first node is reached again
• Search for a designated key

Circular List: Josephus problem : problem statement
Josephus Problem:
1. Find the last remaining survivor from n people standing in a circle.
2. Counting begins at a specific person
3. Moves around the circle in a fixed direction
4. In each step, k-1 people are skipped, and the k-th person is removed.
5. The process repeats until only one person is left.
6. Find that person.

Circular List: Josephus problem : algorithm
The steps involved in solving this problem are:
1. n people are numbered from 1 to n in order and are placed in a circle
2. Starting from a designated start point, we count to kth person.
3. The kth person is eliminated
4. Counting and elimination steps are repeated until a single person is left
5. Original number of that person is the solution.

Doubly Linked List : a few points
• Each node allows movement to the previous previous and the nodes
    • Normally called prev_ and next_ standing for previous and next
• The list node has two pointers – one to the first node and one to the last node
    • Normally called head_ and tail_
• Allows for traversal in both the directions forward and backward

Doubly Linked List : implementation
• Initialize / Deinitialize the list
    • Initialize : Ground both head_ and tail_
    • Deinitialize : traverse and free the nodes. Reinitialize the list

• Insert anywhere in the list
    • Take care of the following cases
         • Empty list : both head_ and tail_ should change
         • Add in the beginning : head_ should change
         • Add at the end : tail_ should change
         • Add in the middle
    • Observe there will be 4 changes to the pointers

Singly vs. Doubly Linked Lists
  Worst-Case Operation (n nodes)                                                     Singly Linked List                   Doubly Linked List

  Move Forward                                                                               1 step                                 1 step


  Move Backward                                                                  n steps (Requires re-traversal)         1 step (Instant fallback)


  Insert Before a Node                                                            n steps (Find predecessor)             1 step (Using prev_ link)


  Delete a Designated Node                                                        n steps (Find predecessor)              1 step (Local isolation)


  Searching for a Key                                                                       n steps                                n steps

                            Priority Queue : unordered list implementation

A priority queue is an abstract data type in which each element is associated with a priority.

Unlike an ordinary queue, where elements are removed according to FIFO (First-In, First-Out) order, a
priority queue removes the component with the highest priority first.

A priority is a number associated with each component. Higher the numeric value, could mean higher
the priority. Or lower the numeric value could mean higher priority.

In our examples, we will assume that higher the numeric value, higher the priority.

Let us relook at the interface of the priority queue before discussing the implementation using
unordered list.

Interface of the priority queue:

The interface of a priority queue is same as that of queue. Component x would have a priority associated
with it.

initialize()                               Create an empty queue

deinitialize()                             Make the queue empty

enqueue(x)                                 Insert x

                                           We may add in number of ways. This in
                                           turn would affect dequeue

dequeue()                                  Remove the element with the highest
                                           priority. This in turn depends how
                                           enqueue operation was done

isEmpty()                                  Check whether the queue is empty

isFull()                                   Check whether the queue is full

Deque :

We must find the node with the highest priority. If there are mode nodes with the same highest priority,
we should select the job which came first. So, such a node will be closed to the front than the other
nodes with the same priority.

If the queue is empty, the program is exited.

There are two parts in the algorithm.

The first is to find the position of the node with the maximum priority. We traverse the normal way.. We
travel till the end of the list. We always keep track of the node with the highest priority – with two
pointers – max_prev and max_pres.

The second part is to capture the job and then remove the node. If it is the first node, the front has to
change. If it is the only node, the rear has to change. Otherwise we should make next of max_prev take
the value of next of max_pres. Then release the max_pres node. Then return the job previously
captured.

Do convince yourself that the order of operations matters.

A question for you – Can we remove the prev pointer from this algorithm?

job_t deque(queue_t *ptr_queue)

{

       if(! is_empty(ptr_queue))

       {

              // traverse

              node_t *prev = NULL;

              node_t *pres = ptr_queue->front_;

              int max_priority = get_priority(&pres->jobx_);

              node_t *max_prev = NULL;

              node_t *max_pres = pres;

              int priority;

              while(pres != NULL)

              {

                      priority = get_priority(&pres->jobx_);
       if(priority > max_priority)

       {

              max_priority = priority;

              max_prev = prev;

              max_pres = pres;

       }



       prev = pres;

       pres = pres->next_;

}



job_t jobx;

jobx = max_pres->jobx_;



if(max_prev == NULL)

{

       ptr_queue->front_ = max_pres->next_;

       if(ptr_queue->front_ == NULL)

       {

              ptr_queue->rear_ = NULL;

       }

}

else

{

       max_prev->next_ = max_pres->next_;

       if(max_pres->next_ == NULL) // last node deleted
                      {

                          ptr_queue->rear_ = max_prev;

                      }

           }

           free(max_pres);

           return jobx;

    }

    else

    {

           printf("queue empty; cannot pop\n");

           exit(1);

    }

}
Efficiency of operations :

Enque : This requires a few operations. We add at the rear without considering the priority.

Deque : This requires walking through the list to find the node with the highest priority. So, the number
of operations is proportional to the number of nodes in the queue.

Important properties of trees:
• Acyclic : Can not start from a node, traverse and come
  back to the same node

• Connected. Any two nodes are connected by a path
  which may go through the root

• A tree of n nodes has n – 1 edges – neither more not
  less.

• Add an edge, we will have a cycle. Remove an edge, we
  will have more than one tree.

                                                                           Binary Tree
Definitiion
 • A binary tree is a tree in which every node has at most
   two children.
 • The two children are distinguished as the
           left child and right child.
 • A binary tree is either:
     • An empty tree, or
     • A root node together with
        two disjoint binary trees called its:
          • left subtree
          • right subtree

Binary representation of any general tree
 • Root of general tree becomes root of the binary tree
 • Child of a node in general tree appears to the left of the
   node in the binary tree
 • Sibling of a node in general tree will appear to the right
   of the node in the binary tree

Binary Search Tree
 • Every node has a key
 • Nodes are inserted based on the key
 • If the key of a node is less than that of the root, it will
   be inserted in the left subtree
 • Otherwise, it will be inserted in the right subtree
