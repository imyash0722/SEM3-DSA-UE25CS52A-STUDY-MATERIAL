Unit 1: List with Header Node¶

8.1 Problem with Regular Linked List (Ordered List)¶

4 Boundary Cases in Insert (from textbook, p.91):¶

Case Condition Special Handling
Empty list head == NULL head = new_node
Insert at beginning new_key < head->key head = new_node
Insert in middle prev->key < new_key < pres->key prev->next = new; new->next = pres
Insert at end pres == NULL prev->next = new; new->next = NULL

Problem (from textbook): "The insert operation has 4 different boundary conditions... Code complexity, 4 separate branches, error-prone."

8.2 Solution: Header Node (Dummy Node)¶

Concept (from textbook p.91-92):¶

  • Empty list has ONE node (the header)
  • Header node's key_ unused (or dummy value)
  • Header's next_ points to first real node (or NULL)
  • head never NULL after initialization

Initialization (from textbook p.91):¶

void init_list(mylist_t* ptr_list)
{
    ptr_list->head_ = (node_t*)malloc(sizeof(node_t));
    ptr_list->head_->next_ = NULL;  // Header's next = NULL
    // header's key_ can be left uninitialized
}

Visual: Empty List with Header (from textbook p.95):¶

ptr_list
   |
   v
[HEADER|•] → NULL
(key unused)

8.3 Simplified Operations¶

Display (Skip Header) (from textbook p.92):¶

void disp_list(mylist_t* ptr_list)
{
    disp_(ptr_list->head_->next_);  // Skip header!
}

Free List (Reset to Empty) (from textbook p.92):¶

void free_list(mylist_t* ptr_list)
{
    // Free all real nodes, keep header
    node_t* q = ptr_list->head_->next_;
    while(q) {
        node_t* r = q->next_;
        free(q);
        q = r;
    }
    ptr_list->head_->next_ = NULL;  // Back to empty
}

8.4 Insertion with Header (Unified!) — Textbook Algorithm¶

Before: 4 Cases (from textbook p.91-92):¶

// Empty list check
if(ptr_list->head == NULL) { ... }

// Beginning check  
if(prev == NULL) { ... }

// Middle/End
else { ... }

After: 1 Case! (from textbook p.94):¶

void insert_list(mylist_t* ptr_list, int key)
{
    // create the node
    node_t* temp = (node_t*)malloc(sizeof(node_t));
    temp->key_ = key; temp->next_ = NULL;

    // traverse from header
    node_t* prev = ptr_list->head_;       // Start AT header
    node_t* pres = ptr_list->head_->next_; // First REAL node

    while(pres != NULL && pres->key_ < temp->key_)
    {
        prev = pres;
        pres = pres->next_;
    }

    // SINGLE insert statement for ALL cases!
    temp->next_ = pres;
    prev->next_ = temp;
}

Why It Works (from textbook):¶

Scenario prev pres Action
Empty header NULL header->next = new
Beginning header 1st node header->next = new
Middle node X node Y X->next = new; new->next = Y
End last node NULL last->next = new; new->next = NULL

All 4 cases unified into 2 lines! (Textbook: "This looks so simple. Is this not easy to read? Our insertion function has become extremely readable.")

8.5 Trace Examples (from textbook p.95-96)¶

Insert 20 (First):¶

Before:  [H] → NULL
prev=H, pres=NULL → loop skips
H→next = 20; 20→next = NULL

Result: [H] → [20] → NULL

Insert 40 (Second):¶

Before:  [H] → [20] → NULL
prev=H, pres=20
Loop: 20<40 → prev=20, pres=NULL
prev=20, pres=NULL
20→next = 40; 40→next = NULL

Result: [H] → [20] → [40] → NULL

Insert 60 (Third):¶

Before:  [H] → [20] → [40] → NULL
Loop: 20<60 (prev=20, pres=40)
      40<60 (prev=40, pres=NULL)
prev=40, pres=NULL
40→next = 60; 60→next = NULL

Result: [H] → [20] → [40] → [60] → NULL

8.6 Header + Tailer (Double Dummy) — Textbook p.95¶

Concept:¶

  • Header at front, Tailer at end
  • Both dummy nodes
  • List always has at least 2 nodes
struct mylist {
    node_t *head_;   // Header
    node_t *tail_;   // Tailer
};

void init_list(mylist_t* l) {
    l->head_ = malloc(sizeof(node_t));
    l->tail_ = malloc(sizeof(node_t));
    l->head_->next_ = l->tail_;
    l->tail_->next_ = NULL;
}

Benefits:¶

  • Insert at end: tailer acts like header for backward traversal
  • Delete last node: no special case
  • Circular list possible: tail_->next_ = head_

8.7 Client Unaffected (ADT Principle)¶

Header File Unchanged:¶

// mylist.h - SAME interface!
void init_list(mylist_t*);
void insert_list(mylist_t*, int);
void disp_list(mylist_t*);
void free_list(mylist_t*);

Client Code:¶

// client.c - NO CHANGES!
mylist_t l; init_list(&l);
insert_list(&l, 20); insert_list(&l, 10);
disp_list(&l); free_list(&l);

Build Process (from textbook p.95):¶

$ make mylist.o      # Recompile implementation only
$ make client.o      # No recompile needed (header unchanged)
$ make a.out         # Relink

Quiz 2: Adding at the end of the list: - a) May require a few operations not proportional to the length of the list - b) Always requires a number of operations proportional to the length of the list ✓ - c) Can never support such an operation - d) None of these

Quiz 3: void what(list_t *ptr_list) { free(ptr_list->head_); } - a) This will free all the nodes in the list - b) This will free all but the first node in the list ✓ - c) This will free the first node; rest of the list is accessible - d) None of these

Quiz 4: The header node is a dummy node added in the beginning of the list. - a) This makes insertion simpler ✓ - b) This makes deletion simpler - c) This makes searching simpler - d) None of these

Quiz 5: The tailer node is a dummy node added at the end of the list. - a) This makes insertion simpler - b) This makes deletion simpler ✓ - c) This makes searching simpler - d) None of these

Summary¶

Aspect Without Header With Header
Empty list head = NULL head->next = NULL
Insert cases 4 separate branches 1 unified case
Code complexity High Minimal
Bugs More boundary errors Fewer
Client impact None (ADT) None (ADT)

MCQ Practice¶

Q1: What does header node eliminate? A: Special case for empty list + insert at beginning

Q2: In header-based insert, prev starts at? A: head (the header node itself)

Q3: In header-based insert, pres starts at? A: head->next_ (first real node)

Q4: Does header node contain valid data? A: No — key_ typically unused/ignored

Q5: How does header simplify end insertion? A: When pres == NULL, prev is last real node; prev->next = new works

Q6: Does client code need to change when adding header? A: No — interface unchanged (ADT principle)
