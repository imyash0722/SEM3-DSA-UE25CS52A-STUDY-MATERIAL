Unit 1: Functions and Pointers¶

1.1 Pass by Value vs Pass by Reference¶

Swap Example - Does Not Work (Pass by Value)¶

// Does not swap the arguments!!
void swap(int x, int y)
{
    int temp = x; x = y; y = temp;
}
int main()
{
    int a = 10; int b = 20;
    swap(a, b);
    printf("a : %d b : %d\n", a, b);
}
Output: a : 10 b : 20 (unchanged!)

Why: C uses pass by value. Copies of a and b get swapped; the original variables are not modified.

Swap Example - Works (Pass by Reference/Pointer)¶

void swap(int *x, int *y)
{
    int temp = *x; *x = *y; *y = temp;
}
int main()
{
    int a = 10; int b = 20;
    swap(&a, &b);
    printf("a : %d b : %d\n", a, b);
}
Output: a : 20 b : 10 (swapped!)

Why: The callee receives pointers to the variables. Dereferencing (*x, *y) gives access to the original variables.

Stack Frame Visualization¶

Pass by Value:                    Pass by Reference:
main() stack:                     main() stack:
a = 10, b = 20                    a = 10, b = 20
swap() stack:                     swap() stack:
x = 10 (copy)                     x = &a (address)
y = 20 (copy)                     y = &b (address)

1.2 Recursion¶

Definition¶

A function calling itself directly or indirectly is recursive. We express the solution in terms of the problem itself but of a smaller size. Requires base case (escape hatch).

Example 1: Count 1s in Binary Representation¶

int what(int n)
{
    if(n == 0)
        return 0;
    else if(n % 2)          // odd
        return 1 + what(n / 2);
    else                    // even
        return what(n / 2);
}

Trace for what(25): 

what(25): n=25 odd → 1 + what(12)
what(12): n=12 even → what(6)
what(6):  n=6  even → what(3)
what(3):  n=3  odd  → 1 + what(1)
what(1):  n=1  odd  → 1 + what(0)
what(0):  n=0        → 0
Unwinding: 0 → 1 → 2 → 2 → 3 → 4 (25 in binary = 11001, has 4 ones)

Call Stack Visualization: 

main() calls what(25)
    what(25) calls what(12)
        what(12) calls what(6)
            what(6) calls what(3)
                what(3) calls what(1)
                    what(1) calls what(0)
                        what(0) returns 0
                    what(1) returns 1
                what(3) returns 2
            what(6) returns 2
        what(12) returns 2
    what(25) returns 4

Example 2: Fast Exponentiation (a^n)¶

int what(int a, int n)
{
    if(n == 0)
        return 1;
    else if(n % 2)           // odd
        return a * what(a * a, n / 2);
    else                     // even
        return what(a * a, n / 2);
}

For what(3, 5) = 3^5 = 243: 

what(3, 5): n=5 odd  → 3 * what(9, 2)
what(9, 2): n=2 even → what(81, 1)
what(81, 1): n=1 odd  → 81 * what(6561, 0)
what(6561, 0): n=0     → 1
Unwinding: 1 → 81 → 81 → 243

Time Complexity: O(log n) vs O(n) for naive multiplication.

1.3 Parameter Passing, Pointers, and Aliasing¶

GCD with Pointer Modification¶

void what(int *p, int *q)
{
    int m = *p; int n = *q;
    while(m != n)
    {
        if(m > n) m -= n;
        else n -= m;
    }
    *p /= m; *q /= n;  // Modifies caller's variables!
}
int main()
{
    int a = 25; int b = 15;
    what(&a, &b);
    printf("%d %d\n", a, b);  // Output: 5 3
}

First Call what(&a, &b): - GCD of 25 and 15 = 5 - a becomes 25/5 = 5, b becomes 15/5 = 3

Aliasing Problem (Dangerous!)¶

what(&a, &a);  // Both pointers point to SAME variable!
printf("%d\n", a);  // Output: 0 (SURPRISE!)

Why? - Both p and q point to a (aliasing) - m = *p = 5, n = *q = 5 (both 5) - Loop not entered (m == n) - *p /= m → a = 5/5 = 1 - *q /= n → a = 1/5 = 0 (integer division!) - Result: a becomes 0!

Key Lesson: Be careful with aliasing when using pointer parameters!

1.4 Separating Interface from Implementation¶

Abstract Data Type Concept¶

// Client code - doesn't know implementation
int is_palindrome(int n);  // Declaration (interface)

int n; scanf("%d", &n);
if(is_palindrome(n))
    printf("%d is a palindrome\n", n);
else
    printf("%d is not a palindrome\n", n);

// Implementation (server) - can change without affecting client
int rev(int n) { ... }
int is_palindrome(int n) { return n == rev(n); }

Benefits: - Client depends on interface (what), not implementation (how) - Implementation can change without breaking client - Multiple implementations possible (library vs custom)

1.5 Multiple Files and Makefiles¶

Project Structure¶

6_server.h    // Interface (declarations)
6_server.c    // Implementation
6_client.c    // Uses the functions

Header (6_server.h)¶

int square(int n);
int cube(int n);

Implementation (6_server.c)¶

#include "6_server.h"
int square(int n) { return n * n; }
int cube(int n) { return n * n * n; }

Client (6_client.c)¶

#include <stdio.h>
#include "6_server.h"
int main() {
    printf("square(5) = %d\n", square(5));
    printf("cube(3) = %d\n", cube(3));
}

Makefile (mymakefile.mk)¶

a.out : 6_client.o 6_server.o
    gcc 6_client.o 6_server.o

6_client.o : 6_client.c 6_server.h
    gcc -c 6_client.c

6_server.o : 6_server.c 6_server.h
    gcc -c 6_server.c

Command: make -f mymakefile.mk

Key Rules: 1. Target depends on sources 2. Commands indented with TAB 3. make only rebuilds what changed 4. Change .h → recompile both .c files 5. Change .c → recompile only that .c

1.6 Function Definition and Call Mechanics¶

Function Definition Structure¶

returntype fnname(<list of parameters with type>)
{
    <stmt>
    return <expr>;
}
Component Description
Return type Type of value returned; void if none
Function name Follows identifier rules
Parameter list Comma-separated type name pairs
Body Statements in { }
Return statement return <expr>; copies value to return location

Function Call Sequence¶

  1. Activation Record Created (stack frame) with: return address, parameters, locals, temps, return value location
  2. Arguments Evaluated (order unspecified!) 
    a = 10; f(a++, a);  // May be f(10,10) or f(10,11) - UNDEFINED
  3. Arguments Copied to parameters (pass by value)
  4. Control Transferred to callee
  5. Function Body Executed
  6. Return: Value copied to return location, frame popped
  7. Caller picks up return value

1.7 Function Declaration vs Definition¶

Problem¶

// Can we call f2 before definition?
// How does compiler know signature?

Solution: Function Declaration (Prototype)¶

int f2(int x, int y);  // Declaration - interface

Interface vs Implementation¶

Aspect Interface (Declaration) Implementation (Definition)
What What function expects How function works
Contains Signature only Full body
Changes Rarely Can change freely
Client sees Yes No (hidden)

Example: 

// Interface
int f2(int x, int y);

// Implementation A
int f2(int x, int y) { return x + y; }

// Implementation B (same interface)
int f2(int x, int y) { int temp = x + y; return temp; }

1.8 Parameter Passing in C¶

Pass by Value (Default)¶

void foo(int x);
int a = 10;
foo(a);
printf("a : %d\n", a);  // 10 - UNCHANGED!
- Argument copied to parameter - Parameter is local variable - Changing parameter ≠ changing argument - Type mismatch → implicit cast (foo(2.5) → foo((int)2.5))

How to Modify Caller's Variable?¶

Pass address (pointer): 

void what(int* q) { *q = 100; }
int a = 10;
what(&a);
printf("a : %d\n", a);  // 100 - CHANGED!
Why it works: Parameter q receives address of a. *q dereferences to get lvalue of a.

1.9 Pointer Manipulation Pitfalls¶

Pitfall 1: Changing Local Pointer Copy¶

void bar(int* q) {
    int temp = 100;
    q = &temp;  // Changes LOCAL copy only!
}
int a = 10;
int *p = &a;
bar(p);
// p still points to a; a unchanged

Solution: Pass Pointer to Pointer¶

void bar(int** q) {
    int temp = 100;
    *q = &temp;  // Changes caller's pointer!
}

1.10 Return Mechanism¶

How Return Works¶

  1. Callee evaluates return expression
  2. Value cast to return type if needed
  3. Copied to temporary return location in stack frame
  4. Caller picks up value from temporary

Returning Pointers - Danger!¶

// OK: Returns pointer to caller's variable
int* one(int* x) { return x; }
int c = 1000;
int *p = one(&c);
printf("%d\n", *p);  // 1000

// DANGER: Returns pointer to LOCAL variable!
int* two() {
    int x = 111;
    return &x;  // x dies when function returns!
}
p = two();
printf("%d\n", *p);  // UNDEFINED BEHAVIOR!

Dangling Pointer: Pointer to memory that no longer exists (stack frame popped).

Summary: Key Points¶

Concept Rule
Parameter passing Always by value in C
Modify argument Pass pointer (&var)
Modify pointer Pass pointer-to-pointer (&ptr)
Return value Copied via temporary
Dangling pointer Never return address of local variable
Function declaration Needed before call for type checking
Interface/Implementation Declaration = interface; Definition = implementation

MCQ Practice¶

Q1: What is the output of: 

void foo(int x) { x = 20; }
int main() { int a = 10; foo(a); printf("%d", a); }
A: 10 (pass by value)

Q2: What is the danger in: 

int* f() { int x = 5; return &x; }
A: Returns address of local variable → dangling pointer → undefined behavior

Q3: How to change a pointer variable in caller? A: Pass int** (pointer to pointer)
