## 1.2 Mathematical Functions vs Programming Functions

### Mathematical Function
- Subset of relation; subset of Cartesian product of sets
- Maps sequence of arguments → single result
- **Pure function:** Same arguments always produce same result
- No side effects; doesn't depend on external state

### Programming Function
- Sequence of code executed when called
- Arguments passed, result returned
- May have side effects (modify global state, I/O, etc.)

### Why Use Functions?
| Reason | Description |
|--------|-------------|
| **Divide and Conquer** | Break complex problems into manageable parts |
| **Sharing** | Libraries avoid reinventing the wheel |
| **Maintenance** | Single point of update; avoid code redundancy |
| **Reliability** | Library functions are well-tested, efficient |
| **Reuse** | Write once, call multiple times |

## 1.3 Function Definition Structure

```c
returntype fnname(<list of parameters with type>)
{
    <stmt>
    return <expr>;
}
```

### Components:
| Component | Description |
|-----------|-------------|
| **Return type** | Type of value returned; `void` if no return |
| **Function name** | Follows identifier rules |
| **Parameter list** | Comma-separated `type name` pairs |
| **Body** | Statements enclosed in `{ }` |
| **Return statement** | `return <expr>;` copies value to return location |

### Examples:
```c
int f1(int x)           { return x * x; }           // returns int
int f2(int x, int y)    { return x + y; }           // two parameters
double f3(int x)        { return sqrt(x); }         // returns double
void f4()               { printf("hello\n"); }      // no return
```

## 1.4 Function Call Mechanics

### Call Syntax:
```c
fnname(arguments ...)
```

### Call Sequence (Step by Step):
1. **Activation Record (Stack Frame) Created** containing:
   - Return address
   - Parameters
   - Local variables
   - Temporary variables
   - Return value location

2. **Arguments Evaluated** (order unspecified!)
   ```c
   a = 10; f(a++, a);  // May be f(10, 10) or f(10, 11) - UNDEFINED
   ```

3. **Arguments Copied to Parameters** (pass by value)

4. **Control Transferred** to callee

5. **Function Body Executed**

6. **Return:** Value copied to return location, frame popped

## 1.5 Function Declaration vs Definition

### Problem:
```c
// Can we call f2 before definition?
// How does compiler know signature?
```

### Solution: **Function Declaration (Prototype)**
```c
int f2(int x, int y);  // Declaration - interface
```

### Interface vs Implementation:
| Aspect | Interface (Declaration) | Implementation (Definition) |
|--------|------------------------|----------------------------|
| **What** | What function expects | How function works |
| **Contains** | Signature only | Full body |
| **Changes** | Rarely | Can change freely |
| **Client sees** | Yes | No (hidden) |

**Example:**
```c
// Interface (header file)
int f2(int x, int y);

// Implementation A
int f2(int x, int y) { return x + y; }

// Implementation B (same interface)
int f2(int x, int y) { 
    int temp = x + y; 
    return temp; 
}
```
Client code compiles against declaration; implementation can change without recompiling client.

## 1.6 Parameter Passing in C

### Pass by Value (Default)
```c
void foo(int x);
int a = 10;
foo(a);
printf("a : %d\n", a);  // 10 - UNCHANGED!
```

**Key Points:**
- Argument copied to parameter
- Parameter is local variable
- Changing parameter ≠ changing argument
- If types don't match: implicit cast (`foo(2.5)` → `foo((int)2.5)`)

### How to Modify Caller's Variable?
**Pass address (pointer):**
```c
void what(int* q) { *q = 100; }
int a = 10;
what(&a);
printf("a : %d\n", a);  // 100 - CHANGED!
```

**Why it works:**
- Parameter `q` receives address of `a`
- `*q` dereferences to get lvalue of `a`
- Assignment modifies original

## 1.7 Pointer Manipulation Pitfalls

### Pitfall 1: Changing Local Pointer Copy
```c
void bar(int* q) {
    int temp = 100;
    q = &temp;  // Changes LOCAL copy only!
}
int a = 10;
int *p = &a;
bar(p);
// p still points to a; a unchanged
```

**Why:** `q` is a copy of the pointer. Changing `q` doesn't affect caller's pointer.

### Solution: Pass Pointer to Pointer
```c
void bar(int** q) {
    int temp = 100;
    *q = &temp;  // Changes caller's pointer!
}
int a = 10;
int *p = &a;
bar(&p);
```

## 1.8 Return Mechanism

### How Return Works:
1. Callee evaluates return expression
2. Value cast to return type if needed
3. Copied to temporary return location in stack frame
4. Caller picks up value from temporary

### Returning Pointers:
```c
// OK: Returns pointer to caller's variable
int* one(int* x) { return x; }
int c = 1000;
int *p = one(&c);
printf("%d\n", *p);  // 1000

// DANGER: Returns pointer to LOCAL variable (DANGLING POINTER!)
int* two() {
    int x = 111;
    return &x;  // x dies when function returns!
}
p = two();
printf("%d\n", *p);  // UNDEFINED BEHAVIOR!
```

**Dangling Pointer:** Pointer to memory that no longer exists (stack frame popped).

## 1.9 Stack Frame Visualization

### For `swap(int *x, int *y)` called from `main()`:

```
main() Stack Frame:
+------------------+
| a = 10           |  ← &a = 0x1000
| b = 20           |  ← &b = 0x1004
| return address   |
+------------------+

swap() Stack Frame (on top):
+------------------+
| x = 0x1000       |  ← points to a
| y = 0x1004       |  ← points to b
| temp             |
| return address   |
+------------------+
```

**Dereferencing:**
- `*x` → accesses `main()`'s `a` at 0x1000
- `*y` → accesses `main()`'s `b` at 0x1004

## Summary: Function Call Flow

```
CALLER                          CALLEE
------                          ------
push arguments                  create stack frame
jump to function                copy args to params
                               execute body
                               compute return value
                               store in return slot
                               pop stack frame
                               jump to return address
pick up return value
continue execution
```

## Key Takeaways

| Concept | Rule |
|---------|------|
| **Parameter passing** | Always by value in C |
| **Modify argument** | Pass pointer (`&var`) |
| **Modify pointer** | Pass pointer-to-pointer (`&ptr`) |
| **Return value** | Copied via temporary |
| **Dangling pointer** | Never return address of local variable |
| **Function declaration** | Needed before call for type checking |
| **Interface/Implementation** | Declaration = interface; Definition = implementation |
