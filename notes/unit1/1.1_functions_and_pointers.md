# Unit 1: Functions and Pointers

## 1.1 Functions

### 1.1.1 Pass by Value vs Pass by Reference (Swap Example)

**Pass by Value (Does NOT swap):**
```c
void swap(int x, int y)
{
    int temp = x; x = y; y = temp;
}
int main()
{
    int a = 10; int b = 20;
    swap(a, b);
    printf("a : %d b : %d\n", a, b);
}
```
**Output:** `a : 10 b : 20` (unchanged)

**Why:** C uses **pass by value**. Copies of `a` and `b` are passed to `swap`. The original variables are not modified.

**Pass by Reference (Works - using pointers):**
```c
void swap(int *x, int *y)
{
    int temp = *x; *x = *y; *y = temp;
}
int main()
{
    int a = 10; int b = 20;
    swap(&a, &b);
    printf("a : %d b : %d\n", a, b);
}
```
**Output:** `a : 20 b : 10` (swapped)

**Why:** The function receives **addresses** (pointers). Dereferencing allows modifying the original variables.

**Stack Frame Visualization:**
- `main()` stack: `a=10, b=20`
- `swap(int *x, int *y)` stack: `x=&a, y=&b`
- `*x` and `*y` dereference to access `main()`'s variables

### 1.1.2 Recursion

**Definition:** A function calling itself directly or indirectly.

**Key Components:**
1. **Base Case (Escape Hatch):** Simple case where recursion stops
2. **Recursive Case:** Problem expressed in terms of smaller instance

**Tracing Recursive Calls:**
- Mark each call with a number to track return positions
- Execution unwinds from base case back up

**Example 1: Count 1s in Binary Representation**
```c
int what(int n)
{
    if(n == 0)
        return 0;
    else if(n % 2)          // odd
        return 1 + what(n / 2);
    else                    // even
        return what(n / 2);
}
```
**Trace for what(25):**
```
what(25) call 1: n=25, odd → 1 + what(12)
what(12) call 2: n=12, even → what(6)
what(6)  call 3: n=6,  even → what(3)
what(3)  call 4: n=3,  odd  → 1 + what(1)
what(1)  call 5: n=1,  odd  → 1 + what(0)
what(0)  call 6: n=0        → return 0
```
**Unwinding:** `0 → 1 → 2 → 2 → 3 → 4` (final answer: 4 ones in binary 11001)

### 1.1.3 Fast Exponentiation (Binary Exponentiation)

**Problem:** Compute a^n efficiently

**Algorithm:**
- If n = 0: return 1
- If n is even: square a, recurse with n/2
- If n is odd: square a, recurse with n/2, multiply by a

```c
int what(int a, int n)
{
    if(n == 0)
        return 1;
    else if(n % 2)              // odd
        return a * what(a * a, n / 2);
    else                        // even
        return what(a * a, n / 2);
}
```

**Example:** what(3, 5) = 3^5 = 243

**Trace:**
```
what(3, 5): n=5 odd → 3 * what(9, 2)
what(9, 2): n=2 even → what(81, 1)
what(81, 1): n=1 odd → 81 * what(6561, 0)
what(6561, 0): n=0 → return 1
```
Unwinding: `1 → 81 → 81 → 243`

**Complexity:** O(log n) vs O(n) for naive multiplication

### 1.1.4 Parameter Passing, Pointers, and Aliasing

**GCD Example with Pointer Modification:**
```c
void what(int *p, int *q)
{
    int m = *p; int n = *q;
    while(m != n)
    {
        if(m > n) m -= n;
        else n -= m;
    }
    *p /= m; *q /= n;  // Modifies caller's variables!
}

int main()
{
    int a = 25; int b = 15;
    what(&a, &b);
    printf("%d %d\n", a, b);  // Output: 5 3
}
```

**First Call:** `what(&a, &b)` 
- GCD of 25 and 15 is 5
- a becomes 25/5 = 5, b becomes 15/5 = 3

**Second Call - Aliasing Problem:**
```c
what(&a, &a);  // Both pointers point to SAME variable!
printf("%d\n", a);  // Output: 0 (SURPRISE!)
```

**Why?**
- Both `p` and `q` point to `a` (aliasing)
- `m = *p = 5`, `n = *q = 5` (both 5)
- Loop not entered (m == n)
- `*p /= m` → `a = 5/5 = 1`
- `*q /= n` → `a = 1/5 = 0` (integer division!)
- **Result:** `a` becomes 0!

**Key Lesson:** Be careful with aliasing when using pointer parameters!

### 1.1.5 Separating Interface from Implementation

**Concept:** Client code shouldn't depend on implementation details.

**Example:** Palindrome Checker
```c
// Interface (header file)
int is_palindrome(int n);

// Client code
int n;
scanf("%d", &n);
if(is_palindrome(n))
    printf("%d is a palindrome\n", n);
else
    printf("%d is not a palindrome\n", n);
```

**Implementation Options:**
```c
// Option 1: Inline logic
int is_palindrome(int n) {
    int rev = 0, m = n;
    while(n) { rev = rev * 10 + n % 10; n /= 10; }
    return m == rev;
}

// Option 2: Helper function
int rev(int n) {
    int r = 0;
    while(n) { r = r * 10 + n % 10; n /= 10; }
    return r;
}
int is_palindrome(int n) {
    return n == rev(n);
}
```

**Benefit:** Client code unchanged when implementation changes.

### 1.1.6 Multiple Files and Makefiles

**Project Structure:**
```
6_server.h    // Interface (declarations)
6_server.c    // Implementation
6_client.c    // Uses the functions
```

**Server Header (6_server.h):**
```c
int square(int n);
int cube(int n);
```

**Server Implementation (6_server.c):**
```c
#include "6_server.h"
int square(int n) { return n * n; }
int cube(int n) { return n * n * n; }
```

**Client (6_client.c):**
```c
#include <stdio.h>
#include "6_server.h"
int main() {
    printf("square(5) = %d\n", square(5));
    printf("cube(3) = %d\n", cube(3));
}
```

**Makefile (mymakefile.mk):**
```makefile
a.out : 6_client.o 6_server.o
    gcc 6_client.o 6_server.o

6_client.o : 6_client.c 6_server.h
    gcc -c 6_client.c

6_server.o : 6_server.c 6_server.h
    gcc -c 6_server.c
```

**How it works:**
- **Target:** `a.out` (executable)
- **Dependencies:** `.o` files
- **Commands:** indented with TAB
- `make -f mymakefile.mk` builds only what changed

**Key Rules:**
1. `.o` file depends on corresponding `.c` and `.h`
2. Change `.h` → recompile both `.c` files
3. Change `.c` → recompile only that `.c`
4. Only link if `.o` files changed

## Summary of Key Points

| Topic | Key Takeaway |
|-------|--------------|
| Pass by value | Copies made; original unchanged |
| Pass by reference (pointers) | Addresses passed; can modify original |
| Recursion | Base case + recursive case; trace with call numbers |
| Binary exponentiation | O(log n) using divide-and-conquer |
| Aliasing | Same address through multiple pointers; dangerous! |
| Interface/Implementation | Header file = contract; .c file = implementation |
| Makefile | Dependency tracking; incremental builds |
